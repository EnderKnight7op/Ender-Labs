# Security Policy

**Last updated:** October 4, 2026

Ender Labs takes the security of Garnet and the information it processes seriously.

If you believe you have discovered a security vulnerability, please report it responsibly rather than publicly disclosing the issue before it can be investigated.

## 1. Reporting a Vulnerability

Please report security issues through the [Ender Labs Discord server](https://dsc.gg/enderlabs).

When possible, include:

- A clear description of the vulnerability
- The affected feature or component
- Steps needed to reproduce the issue
- The potential impact
- Any relevant logs, screenshots, or proof-of-concept information that can be shared safely

Please do not include passwords, Discord tokens, private user information, or other sensitive credentials in a report.

## 2. What to Expect

We will review reports as soon as reasonably possible.

Depending on the severity and complexity of an issue, investigation and remediation may take different amounts of time.

We may contact you for additional information if needed.

## 3. Responsible Disclosure

Please allow us reasonable time to investigate and address a reported vulnerability before publicly disclosing technical details.

Please do not:

- Access, modify, or delete data that does not belong to you
- Disrupt Garnet or Discord services
- Perform denial-of-service or similar attacks
- Social-engineer users or staff
- Publish credentials, tokens, or private information discovered during testing

Only test against systems and data you are authorised to access.

## 4. Security Practices

Depending on the environment and feature, Ender Labs may use measures such as:

- Access controls and least-privilege permissions
- Secure handling of application credentials
- Database access controls
- Dependency updates and maintenance
- Logging and monitoring where appropriate
- GitHub repository access controls for private source code

Security practices may evolve as Garnet develops.

## 5. Credential Protection

Discord bot tokens, API credentials, database credentials, and other secrets must not be intentionally published in source code or public repositories.

If a credential is accidentally exposed, it should be treated as compromised and rotated or revoked as soon as possible.

## 6. Scope

This policy covers security issues affecting Garnet and Ender Labs systems.

Issues belonging exclusively to Discord or another third-party service should be reported to the relevant provider as well.

## 7. Contact

Security reports can be submitted through the [Ender Labs Discord server](https://dsc.gg/enderlabs).

For sensitive reports, avoid posting confidential details in a public channel. Ask for an appropriate private reporting method instead.

---

This policy describes the current security reporting process and may be updated as the project evolves.
